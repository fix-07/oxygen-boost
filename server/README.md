# Oxygen Boost — الخادم

واجهة برمجية بـ Express فوق MongoDB — تُخزّن المنتجات وأسعارها، تستقبل الطلبات
وتحسب مبالغها ذرّياً، وتُرسل إشعار بريد عبر Gmail SMTP.

**القاعدة الأساسية:** كل سعر ومبلغ يُقرأ ويُحسب من قاعدة البيانات فقط. العميل يرسل
`productId`/`qty` لا غير — وأي محاولة لإرسال `price` أو `total` تُرفَض بالحالة `400`
بدل أن تُتجاهل بصمت.

## البنية

```
server/
  config.js              إعدادات من متغيّرات البيئة فقط
  db.js                  اتصال MongoDB + بذر الكتالوج الأولي (غير هدّام)
  auth.js                تجزئة كلمات المرور (scrypt) + جلسات JWT
  validate.js            تحقّق صارم من المدخلات (قائمة سماح)
  mailer.js              إشعار بريد Gmail SMTP
  models/                مخطّطات Mongoose (Product, Order, User, Coupon, Settings)
  services/               منطق العمل (إنشاء الطلبات، حساب الخصم، إلخ) — منفصل عن الراوتات
  routes/
    public.routes.js       المسارات العامة (الكتالوج، الطلبات، التتبّع، الكوبونات)
    admin.routes.js        مسارات المشرف (JWT مطلوب)
  app.js                  تجميع الوسطاء والراوتات فقط
  index.js                نقطة التشغيل
  seed-admin.js           إنشاء/تحديث حساب المشرف
```

## التشغيل

```bash
cd server && npm install
```

انسخ `.env.example` إلى `.env` واملأ القيم:

```bash
cp .env.example .env
```

أنشئ عنقوداً مجانياً على [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register)
وضع سلسلة الاتصال في `MONGODB_URI` (من Atlas: Connect → Drivers).

ولّد سرّ التوقيع:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

أنشئ حساب المشرف (يقرأ `ADMIN_EMAIL` و `ADMIN_PASSWORD` من `.env` — احذف كلمة المرور من الملف بعدها):

```bash
npm run seed:admin
```

ثم شغّل الخادم:

```bash
npm run dev
```

عند أول تشغيل، يُنشئ الخادم تلقائياً كتالوج المنتجات وكوبونَي الافتتاح وإعدادات الشحن
الأولية في MongoDB — هذا البذر **لا يدهس** أي سعر أو كوبون عدّله المشرف لاحقاً.

## بريد Gmail

Gmail لا يقبل كلمة مرور الحساب من SMTP. فعّل التحقّق بخطوتين ثم أنشئ **كلمة مرور تطبيقات**
من <https://myaccount.google.com/apppasswords> وضعها في `GMAIL_APP_PASSWORD`.
إذا تُركت فارغة يعمل الخادم طبيعياً ويُسجّل الطلبات دون إرسال بريد.

## نقاط الوصول

| الطريقة  | المسار                  | الصلاحية | الوظيفة                                    |
| -------- | ----------------------- | -------- | ------------------------------------------- |
| `GET`    | `/health`                | عام      | فحص الحياة                                  |
| `GET`    | `/products`               | عام      | الكتالوج بالأسعار والمخزون الحقيقيَين        |
| `GET`    | `/settings`                | عام      | تكلفة التوصيل وعتبة التوصيل المجاني          |
| `POST`   | `/coupons/validate`         | عام      | التحقّق من كود خصم بعينه (لا يكشف القائمة)  |
| `POST`   | `/orders`                    | عام      | إنشاء طلب (سلة متعددة الأصناف)              |
| `GET`    | `/orders/:number`             | عام      | تتبّع طلب برقمه (هاتف اختياري للتأكيد)      |
| `POST`   | `/admin/login`                  | عام      | تسجيل دخول المشرف → رمز JWT                  |
| `GET`    | `/admin/products`                 | مشرف     | كل المنتجات (مفعّلة وغير مفعّلة)             |
| `PATCH`  | `/admin/products/:id`               | مشرف     | تعديل الاسم/السعر/المخزون/التفعيل            |
| `GET`    | `/admin/orders`                       | مشرف     | آخر الطلبات                                  |
| `PATCH`  | `/admin/orders/:number`                 | مشرف     | تعديل الحالة أو علامة "مقروء"                |
| `GET`    | `/admin/coupons`                          | مشرف     | كل أكواد الخصم                               |
| `POST`   | `/admin/coupons`                            | مشرف     | إنشاء/تحديث كود خصم                          |
| `DELETE` | `/admin/coupons/:code`                        | مشرف     | حذف كود خصم                                  |
| `PATCH`  | `/admin/settings`                               | مشرف     | تعديل تكلفة التوصيل وعتبة التوصيل المجاني    |

### إنشاء طلب

```bash
curl -X POST http://localhost:4000/orders \
  -H "Content-Type: application/json" \
  -d '{
    "items": [{"productId":"bundle-60","qty":1}],
    "couponCode": "OXY10",
    "customer": {"name":"محمد علي","phone":"0912345678","city":"طرابلس","address":"حي الأندلس، قرب الجامع"}
  }'
```

الحقول المسموحة: `items` (مصفوفة `{productId, qty}`)، `couponCode` (اختياري)، و`customer`
بحقول `name`/`phone`/`city`/`address`/`notes`. أي حقل آخر (بما فيه أي سعر أو إجمالي) يُرفَض.

## ما الذي يحمي هذا الخادم

- **السعر من القاعدة حصراً** — `POST /orders` يقرأ سعر كل منتج من MongoDB ويحسب المجموع
  والخصم والتوصيل داخل الخادم. لا يوجد أي مسار يقرأ مبلغاً من جسم الطلب.
- **قائمة سماح صارمة** للحقول — إرسال `price` أو `total` يُرجع `400` باسم الحقل المرفوض.
- **معاملة MongoDB ذرّية** لكل طلب: خصم المخزون (بشرط التوفّر) وإدراج الطلب يتمّان معاً
  أو يتراجعان معاً، فلا بيع زائد عند الطلبات المتزامنة ولا مخزون يُخصَم بلا طلب مقابل.
  (يتطلّب replica set — متوفّر تلقائياً على Atlas.)
- **الأسعار أعداد صحيحة** بالوحدة الصغرى (× 100) داخلياً، فلا أخطاء فاصلة عائمة في المحاسبة.
- **كلمات المرور بـ scrypt** بملح عشوائي ومقارنة ثابتة الزمن، مع تجزئة وهمية عند عدم وجود
  المستخدم حتى لا يكشف زمن الاستجابة البُرد المسجّلة.
- **جلسات JWT** بمدة صلاحية، والسرّ من البيئة — والخادم يرفض الإقلاع في وضع الإنتاج بدونه.
- **كوبونات لا تُعرَض قائمتها للعامة** — `/coupons/validate` يتحقّق من كود بعينه فقط.
- **تحديد المعدّل**: ٣٠٠ طلب/١٥ دقيقة عموماً، حدّ مخصّص للطلبات، و٥ لمحاولات الدخول.
- **helmet** لترويسات الأمان، و**CORS** بقائمة مصادر محدّدة، وحدّ ١٠ كيلوبايت لجسم الطلب.
- **تهريب HTML** لبيانات العميل داخل بريد الإشعار.
- **لا تسريب للأخطاء** — تفاصيل الاستثناءات تبقى في السجلّ ولا تصل للعميل.

## ملاحظات قبل الإنتاج

- `.env` مستثنى في `.gitignore` — لا ترفعه أبداً.
- اضبط `TRUST_PROXY=1` خلف Nginx أو Render، وإلا فسيرى تحديد المعدّل عنوان الوسيط لكل الزوار.
- `ORDER_RATE_LIMIT` افتراضه ٢٠ لكل IP كل ١٥ دقيقة. كثير من العملاء في ليبيا يشتركون في نفس
  عنوان IP عبر شبكة المشغّل، فراقب السجلّ وارفع القيمة إن رأيت حجباً لطلبات حقيقية.
- خذ نسخة احتياطية دورية من قاعدة البيانات (Atlas يوفّر نسخاً احتياطية تلقائية في الخطط المدفوعة).
